# TestFlight / App Store owner actions

This application is not ready for distribution. Complete `STATUS.md` and the authenticated/device/hardware checklist first.

1. Approve final reverse-DNS bundle ID (`com.resuto.ipadpos` is a placeholder), Apple Developer team, signing identities and provisioning. Configure them in private Xcode/CI settings; never commit private keys, profiles, Apple API keys or customer credentials. Simulator jobs use ad hoc signing with a test-only `RESUTOTEST.` prefix and require no Apple credentials. Release signing must replace that command-line prefix with the authorized team profile; inspect the generated application identifier and Keychain entitlement set.
2. Staging Supabase origin/public publishable key are verified. Supply dedicated staff test accounts/branch roles through approved secret configuration; follow `STAGING.md`. Validate Supabase password/MFA policy and native authentication behavior. No guessed account or service-role login.
3. Complete backend dependency agreements with Claude: atomic quotes/reconciliation/device policy and prioritized missing native workflows. Add authenticated UI/security tests with dedicated staging data, not disabled authorization.
4. Select supported printer models/interfaces and actual test iPads, then run the hardware/device matrix. Approve any vendor SDK license, pinned version, diagnostic data and privacy manifest before including it.
5. Add approved high-resolution app icon/launch branding, screenshots for supported iPads, bilingual App Store metadata, support/privacy URLs and accessibility review. Existing native app uses system launch screen and SF Symbols; release artwork remains unfinished.
6. Review privacy disclosures against actual authentication/order data and Supabase/Resuto processing. Privacy manifest declares no tracking, UserDefaults reason CA92.1 and preliminary app-functionality collection of identifiers/contact/order content/purchase history; validate these declarations and App Store nutrition labels with the owner/privacy review. AES/HTTPS encryption export declaration must be reviewed for actual distribution jurisdictions.
7. Archive signed Release on approved Xcode; validate device performance/energy/memory, network privacy prompts, locked-storage/crash recovery, API environment isolation and shipping entitlement set. Upload to TestFlight only with authorized signing access. Run App Store validation and supervised pilot before rollout.
8. Prepare deployment/rollback policy, native/backend contract compatibility window, support diagnostics without PII and managed-device lost/revocation procedure. No native production API environment or infrastructure has been changed here.

PR base is always `feature/ipad-pos`. CI and any review branch must not merge into `main` or Claude's development branch. Shared infrastructure and production deployment require explicit owner approval.
